# Core 1 v1 — контракт legacy-ошибок

## Представление ошибки

Каждая ошибка возвращается как результат модуля, а не исключение процесса и не число `0`:

| Поле | Смысл |
|---|---|
| `code` | стабильный код Core 1 |
| `excel_error` | исходный маркер: `#N/A`, `#REF!`, `#VALUE!`, `#DIV/0!` или `null` |
| `module` | модуль, где ошибка стала активной |
| `source_cells` | доказанные Excel-ячейки |
| `trigger` | нормализованное условие активации |
| `affected_outputs` | поля, которым нельзя доверять |
| `severity` | `warning`, `unsupported`, `error` |
| `message_ru` | пользовательская диагностика без предложения фиктивного результата |

## Обязательные случаи

| Code | Trigger | Affected module | Excel result | Core compatibility result | User-facing diagnostic |
|---|---|---|---|---|---|
| `PURLIN_STEP_500_REF` | расчёт выбирает колонку кандидата с шагом ровно `500` мм и этот кандидат участвует в итоговом выборе | `PurlinCalculator` | `#REF!` из `Расчеты*!B73:B76` или `B128:B131`, далее через `D81:D84`/`D136:D139` | typed `#REF!`; `purlin_profile`, `purlin_step_mm`, обе массы и зависимый `kg_per_m2` недоступны | «Исходный Excel содержит разрушенную ссылку для шага прогона 500 мм; результат сохранён как legacy #REF!.» |
| `SPAN_24_LEGACY_NA` | `span_m=24` и активная таблица `24м` передаёт ошибку в выбранный путь | `FrameSelector` / `StructuralSummary` | активный `#N/A` | typed `#N/A`; не выбирать соседний пролёт и не подставлять запасной профиль | «Для пролёта 24 м исходная книга возвращает #N/A; совместимый результат отсутствует.» |
| `WINDOW_EN_SWITCH_UNREACHABLE` | legacy Excel пытается активировать EN через пустой `J20` | `WindowGirtCalculator` | условие `J20="да"` ложно; Excel остаётся в SP-ветке | только legacy compatibility trace; новый Core использует явный `normative_system` | «В исходной книге legacy EN-ветка не активируется: управляющая ячейка J20 не вычисляется.» |
| `UNKNOWN_WINDOW_DOMAIN` | исторический/старый сценарий без доказанного parity oracle | `WindowGirtCalculator` | legacy trace не даёт доказанного результата для старого сценария | не использовать как blocker нового API; новый Core возвращает module boundary до реализации | «Для legacy оконного сценария отсутствует числовой oracle.» |
| `WINDOW_CITY_DATASET_VERSION_CONFLICT` | city lookup выходит за доказанный локальный snapshot | `ClimateResolver` / `WindowGirtCalculator` | локальный exact lookup не подтверждён для этого ключа | `unknown_domain`; внешний ID3 не загружается автоматически | «Город отсутствует в подтверждённом локальном climate-наборе.» |
| `WINDOW_EN_INPUT_SOURCE_UNAVAILABLE` | legacy trace требует внешнего/не доказанного EN input source | `WindowGirtCalculator` | локальные EN blocks не могут быть воспроизведены в старом режиме | не применять к новому API при явном `normative_system=SP_RK_EN` | «Legacy EN-источник недоступен; новый Core использует локальную ветку напрямую.» |
| `LOOKUP_NO_MATCH` | exact `MATCH`/`VLOOKUP` не находит city, covering, deck или profile | модуль-владелец lookup | `#N/A` | typed `#N/A`; кандидат исключается только если исходная downstream-формула явно это делает | «Значение отсутствует в legacy-справочнике.» |
| `NO_ELIGIBLE_PROFILE` | все кандидаты исключены штатными `#N/A` или sentinel-условиями | `PurlinCalculator` или `WindowGirtCalculator` | `#N/A` либо sentinel `999999999`, в зависимости от исходной цепочки | сохранить соответствующий маркер; не выбирать ближайший профиль | «В области исходного Excel нет допустимого профиля.» |
| `LEGACY_VALUE_ERROR` | в активный выбранный путь попадает `#VALUE!` | любой | `#VALUE!` | typed `#VALUE!` | «Исходная формула получила несовместимый тип данных.» |
| `LEGACY_DIV_ZERO` | в активный выбранный путь попадает деление на ноль | любой | `#DIV/0!` | typed `#DIV/0!` | «Исходная формула выполняет деление на ноль.» |
| `INPUT_DOMAIN_UNKNOWN` | числовой input находится вне доказанного подмножества v1 | `InputValidation` | поведение не доказано | `unsupported`, `excel_error=null` | «Значение находится вне подтверждённой области Core 1 v1.» |

## Правила распространения

1. Ошибка становится пользовательской, только если достигает выбранного результата; ошибки невыбранных кандидатов остаются diagnostics уровня trace.
2. `#N/A` не превращается автоматически в «нет профиля»: значение классифицируется по конкретному downstream.
3. Строки `"0"`, `"-"`, `""`, пустая ячейка и числовой ноль не являются ошибками и не взаимозаменяемы.
4. `StructuralSummary` не вычисляет частичный `kg_per_m2`, если один из включённых компонентов имеет активную ошибку.
5. Core 2 получает `compatibility_diagnostics` и не имеет права самостоятельно исправлять или обходить ошибку Core 1.
