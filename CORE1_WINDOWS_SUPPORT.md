# Core 1 v1 — поддержка оконного модуля

## Что доказано локально

Основная книга содержит:

- геометрию, glazing и пользовательские входы окон/проёмов;
- явный `window_type=1..5`, напрямую соответствующий legacy controller `Лист1!B8`;
- таблицу кандидатов оконных профилей и проверки на листе `Расчет`;
- выбранные результаты `Расчет!B21:B23,B26:B28`;
- представление результатов `Лист1!B24:D33,B37:D46`;
- 820 формул проверок в `Расчет!AK4:AK413` и `AN4:AN413`;
- коэффициентную логику `IF(Лист1!J19="да";1/1,05;1)`;
- downstream расчёт `Лист1!O28` (кг/м²) и `O29` (т), поступающий в `вывод!D68:E68`.

Эти формулы и профильные таблицы можно перенести автономно. Наличие формул не означает, что для произвольного сценария доказаны их ветровые входы.

## Локальная эквивалентность исторических ссылок

| Цепочка | Локальный источник в основной книге | Состояние |
|---|---|---|
| `Лист1!J18 → K18 → J19` | `Города п.К`, `снегветер`, локальная lookup-цепочка | локальный equivalent доказан; fuzzy/fallback запрещены |
| `Расчет!D9/F9`, SP branch | локальный `Ветер СП!G25:G26` | формула и таблица есть; cached `#N/A` сохраняется как legacy state |
| `Расчет!D9/F9`, EN branch | локальный `Ветер по СП РК EN!D28:D29` и его `Z:AC` blocks | формулы и входные blocks есть; новый Core активирует их через `normative_system=SP_RK_EN` |
| выбор EN/SP | Core API `normative_system` | для KZ «нет»→`SP_20`, «да»→`SP_RK_EN`; `Лист1!J20` не читается |

Внешние ID3/ID4/ID5 — legacy/redundant ссылки и не являются runtime blockers.
Книга v2.0 не является автоматической заменой: она использует другие значения
и изменённые формулы нагрузки.

## Гарантии Core 1 v1

| Сценарий | Гарантия |
|---|---|
| все параметры окон равны нулю | `SUPPORTED`: оконный подбор не требуется; нулевой вклад проёмов воспроизводится |
| только ворота/двери, окна нулевые | локальный `OpeningMassCalculator` может считать доказанный путь; до расширения числового domain результат должен быть покрыт golden test |
| сохранённый workbook fixture | разрешено сравнить и вернуть cached legacy trace, явно помеченный `fixture_only`; это не универсальный расчёт |
| ненулевые окна / новый город / новая геометрия | формульная цепочка `SUPPORTED` для реализации; отсутствие non-zero golden oracle блокирует только `PARITY_PROVEN`, а не реализацию |
| `windows.enabled=true` | требуется `window_type` 1..5; типы остаются canonical labels `Тип 1`…`Тип 5` |

## Результаты

При поддержанном сценарии модуль может гарантировать:

- отсутствие оконного вклада для нулевых inputs;
- структуру выходов `window_girts`, `openings_weight_kg_per_m2`, `openings_weight_t`, `openings_weight_kg`;
- точную конверсию `openings_weight_kg = openings_weight_t × 1000`;
- сохранение Excel errors и sentinels.

`WindowGirtCalculator` реализован по локальной формульной цепочке и возвращает
профили, utilization, сталь, массу и development trace. Запрещено использовать
нули, ближайший профиль или v2.0 как молчаливый fallback; локальные `Ветер СП`
и `Ветер по СП РК EN` выбираются напрямую по `normative_system`.

## Условия будущего расширения

Оконный parity-domain можно расширить только после закрытия локальных пробелов:

1. добавлен независимый non-zero golden набор для утверждения `PARITY_PROVEN`;
2. реализованы и покрыты тестами формулы `WindowGirtCalculator` для типов 1–5.

Внешняя книга и corrected mode для этого не требуются. Core 1 v1 не содержит
corrected mode.
