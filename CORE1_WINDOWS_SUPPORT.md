# Core 1 v1 — поддержка оконного модуля

## Что доказано локально

Основная книга содержит:

- геометрию и пользовательские входы окон/проёмов;
- таблицу кандидатов оконных профилей и проверки на листе `Расчет`;
- выбранные результаты `Расчет!B21:B23,B26:B28`;
- представление результатов `Лист1!B24:D33,B37:D46`;
- 820 формул проверок в `Расчет!AK4:AK413` и `AN4:AN413`;
- коэффициентную логику `IF(Лист1!J19="да";1/1,05;1)`;
- downstream расчёт `Лист1!O28` (кг/м²) и `O29` (т), поступающий в `вывод!D68:E68`.

Эти формулы и профильные таблицы можно перенести автономно. Наличие формул не означает, что для произвольного сценария доказаны их ветровые входы.

## Что зависит от недоказанных источников

| Цепочка | Недостающий источник | Последствие |
|---|---|---|
| `Лист1!J18 → K18 → J19` | точная ID 3 `СП РК EN!B:C` | нельзя гарантировать Kazakhstan membership и коэффициент `1/1,05` для произвольного города |
| `Расчет!D9/F9`, SP branch | старая ID 4 `Ветер СП!G25:G26` | нельзя пересчитать ветровую нагрузку окна для новых inputs |
| `Расчет!D9/F9`, EN branch | ID 4 `Ветер по СП РК EN!D28:D29` и ID 5 inputs | нельзя пересчитать EN-нагрузку |
| выбор EN/SP | `Лист1!J20` | ячейка пуста и не имеет producer; исправление на `J19` запрещено |

Книга v2.0 не является автоматической заменой: она использует другие значения и изменённые формулы нагрузки.

## Гарантии Core 1 v1

| Сценарий | Гарантия |
|---|---|
| все параметры окон равны нулю | `SUPPORTED`: оконный подбор не требуется; нулевой вклад проёмов воспроизводится |
| только ворота/двери, окна нулевые | локальный `OpeningMassCalculator` может считать доказанный путь; до расширения числового domain результат должен быть покрыт golden test |
| сохранённый workbook fixture | разрешено сравнить и вернуть cached legacy trace, явно помеченный `fixture_only`; это не универсальный расчёт |
| ненулевые окна / новый город / новая геометрия | `UNSUPPORTED_FOR_PARITY`; `WindowGirtCalculator` не возвращает инженерный профиль |
| принудительный запрос EN | `WINDOW_EN_SWITCH_UNREACHABLE`, затем при override — `WINDOW_EN_INPUT_SOURCE_UNAVAILABLE` |

## Результаты

При поддержанном сценарии модуль может гарантировать:

- отсутствие оконного вклада для нулевых inputs;
- структуру выходов `window_girts`, `openings_weight_kg_per_m2`, `openings_weight_t`, `openings_weight_kg`;
- точную конверсию `openings_weight_kg = openings_weight_t × 1000`;
- сохранение Excel errors и sentinels.

При неподдержанном оконном сценарии числовые поля и профиль возвращаются как unavailable вместе с diagnostics. Запрещено использовать нули, ближайший профиль, локальный `Ветер СП` или v2.0 как молчаливый fallback.

## Условия будущего расширения

Оконный parity-domain можно расширить только после одного из решений:

1. получены и versioned точные datasets ID 3/4/5; или
2. владелец методики письменно утверждает другую canonical-версию и отдельный, не legacy, режим.

Оба варианта требуют нового golden-набора. Core 1 v1 не содержит corrected mode.
