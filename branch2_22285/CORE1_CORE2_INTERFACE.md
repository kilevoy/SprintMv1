# CORE1_CORE2_INTERFACE

## Статус интерфейса

Прямой ссылки из `22285.xlsx` на основную книгу подбора сечений, таблицу нагрузок или подбор оконных ригелей не обнаружено. Внутри этого файла есть только внешние ссылки на десять прайсов/справочников. Поэтому «Core 1 → Core 2» восстанавливается сейчас как предполагаемый бизнес-интерфейс, а не как доказанная Excel-связь.

## Доказанные поля Core 2

Core 2 принимает/хранит: номер ТЗ, город, объект, пролёт, длину, высоту, шаг рам, наружную и внутреннюю обшивку, толщину утепления кровли и стен, площадь перегородок, уровень ответственности, степень огнестойкости и выбор альбом/проект.

## Вероятные поля от Core 1

Логически Core 1 мог бы передавать климатические зоны, выбранные сечения, типы рам, оконные ригели, ворота/двери/окна и структурные количества. Но в данном файле нет прямых ссылок на эти источники, а `C5/D5` не используются формулами. Все такие связи помечаются `UNKNOWN — NEEDS SOURCE CONFIRMATION`.

## Что Core 2 считает самостоятельно

Книга самостоятельно содержит расчёты количества профилей/листов/крепежа, массу и стоимость строк, суммы BOM, упаковку, укрупнённые коммерческие категории и часть рамников из externalLink 10.

## Требуемая проверка

Нужно сопоставить адреса/идентификаторы из первой части Sprint M с полями `22285.xlsx` на одном и том же ТЗ и на одном рабочем наборе прайсов. До этого нельзя считать расчётную границу Core 1/Core 2 закрытой.

## Правило владения

Пока Core 1 не предоставит идентифицированный результат с единицей и составом, Core 2 владеет своими локальными quantities/costs, но не получает право объявлять их заменой инженерного результата Core 1. Передача должна быть по ID ТЗ и типу конструктивной ветки, а не по совпадению названия профиля.
