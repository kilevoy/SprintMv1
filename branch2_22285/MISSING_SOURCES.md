# MISSING_SOURCES

## Обязательные отсутствующие файлы

1. Все десять внешних источников из [EXTERNAL_DEPENDENCIES.md](EXTERNAL_DEPENDENCIES.md), включая точные версии прайсов и `рамники_нов.xls`.
2. Каноническая таблица климатических нагрузок/городов и правило её связи с `C5:D5`.
3. Исходник или экспорт первой части Sprint M, если `22285.xlsx` должен получать от неё сечения и конструктивные количества.
4. Описание значений кодов `I3`, `I4`, `I13`, `G8`, `G9` и подтверждение единиц `H` в каждом справочнике.

## Желательные подтверждения

- дата и версия каждого прайса;
- какой из дублирующихся путей `[2]/[3]/[4]/[8]` является каноническим;
- какой из вариантов `[5]/[6]/[9]` является каноническим;
- авторское пояснение к коэффициентам `1.02`, `1.05`, `1.1`, `1.15`, `1.17`, `1.2`;
- решение, должны ли строки с `*0` оставаться в ядре как сценарные ветви;
- ожидаемые тестовые результаты хотя бы для одного ТЗ на каждом типе пролёта.

## Приоритет закрытия

Сначала нужны external ID 1 и 10. Они закрывают основной каталог/массу и рамники/типовые элементы. Затем нужны ID 7 и 2. После них можно закрывать изолированные группы ID 4, 5, 6, 3, 8 и 9. Полная последовательность и локальные адреса приведены в [SOURCE_REQUIREMENTS.md](SOURCE_REQUIREMENTS.md) и в source cards [EXTERNAL_DEPENDENCIES.md](EXTERNAL_DEPENDENCIES.md).

## Данные для климатической неопределённости

Чтобы закрыть `C5:D5`, нужен не только файл с городами, но и доказанная цепочка выбора: название поля, справочник города/зоны, правило преобразования в расчётный коэффициент, адрес результата в Core 1 и пример для всех пяти листов. В текущем `22285.xlsx` есть только кэш `C5=3`, `D5=2`; внешняя ссылка и локальный dependent отсутствуют.

## Данные для интерфейса Core 1 → Core 2

Нужен экспорт Core 1 с идентификаторами ТЗ и единицами минимум для: снег, ветер, выбранные профили рам/колонн/прогонов, шаг прогонов, связи/затяжки/распорки, болты/пластины, масса каркаса и структурная масса. Без этих полей нельзя отличить передачу результата от повторного расчёта.
