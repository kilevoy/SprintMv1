# DUPLICATED_LOGIC

## Цель

Не допустить двух независимых алгоритмов для одной инженерной величины при будущей сборке Core 1/Core 2. Ниже разделены доказанные дубли, потенциальные дубли и независимые расчёты.

| Величина / ветка | Что видно в `22285.xlsx` | Классификация | Действие для интерфейса |
|---|---|---|---|
| `frame_count` / число рам | `I17=CEILING(C9/C11+1,1)` и отдельная геометрическая `J16` | AUTHORITATIVE CORE 2 для этого файла; потенциальный LEGACY DUPLICATE с Core 1 | передавать из Core 1 только после доказательства, что Core 1 считает ту же величину и в тех же единицах |
| `span`, `length`, `height`, `frame_step` | используются локально для количеств и площади | AUTHORITATIVE CORE 2 как входы/драйверы | Core 1 должен передавать исходные значения, но Core 2 не должен повторно выбирать их |
| `snow`, `wind` | `C5:D5` заполнены, но dependents не обнаружены | UNKNOWN, не доказанный duplicate | сначала закрыть Core 1/климатический источник |
| профили каркаса | названия и количества есть в BOM, сортамент/масса часто внешние | UNKNOWN: возможна повторная выборка Core 1 | сравнить с фактическими сечениями Core 1; не считать текст профиля интерфейсом |
| оконные ригели/проёмы | в этой книге нет доказанного прямого входа из книги ригелей | UNKNOWN | нужен Core 1 output или отдельный source mapping |
| `purlin_profile`, `purlin_step` | отдельного доказанного поля интерфейса нет | REQUIRES CORE 1 / UNKNOWN | не реконструировать из похожих названий |
| связи, затяжки, распорки, болты, фасонки/пластины | есть как BOM-позиции/вспомогательные строки и количества | INDEPENDENT CALCULATION в Core 2 до появления Core 1 результата | сравнить позиционно; при совпадении не объединять автоматически |
| масса строк | `G=C*H`, затем суммы `G` | AUTHORITATIVE CORE 2 для BOM-массы; upstream `H` зависит от источников | Core 1 может иметь конструктивную массу, но это другой кандидат на duplicate |
| `frame_weight`, `structural_weight` | укрупнённые суммы и коммерческие строки | UNKNOWN / возможный LEGACY DUPLICATE | нужен mapping состава, а не только числовое совпадение |
| cost, markup, packaging, total | цены и коэффициенты считаются внутри Core 2 | AUTHORITATIVE CORE 2 | не принимать стоимость из Core 1 без отдельного контракта |

## Ключевой вывод

На текущих данных доказанных случаев, где Core 1 и Core 2 напрямую считают одну величину через ссылку, нет. Есть потенциальные дубли: рамная геометрия, конструктивная масса, сечения и элементы каркаса. Они остаются `UNKNOWN`, пока не предоставлены результаты Core 1 с идентификаторами и единицами.
