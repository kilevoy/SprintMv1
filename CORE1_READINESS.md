# Готовность Core 1

## Итоговый статус

# PARTIALLY BLOCKED

## A. Можно ли реализовать Core 1 без Excel runtime?

Да. Используемые функции, lookup, подбор кандидатов и error semantics реализуемы автономно. Excel не нужен как runtime. Оконная формульная цепочка локально доказана для реализации; полная 1:1 parity пока ждёт non-zero golden oracle.

## B. Можно ли отказаться от старых внешних Excel-книг?

- От `[1]` и `[2]` для активного подбора прогонов — да: расчёт локализован, 1 756 внешних ячеек доказанно равны локальным.
- От самих файлов как runtime — да, если нужные списки/таблицы извлечены в versioned static data.
- Исторические `[3]`, `[4]` и `[5]` не загружаются runtime: canonical — локальные листы основной книги; их формульные токены классифицированы как `LEGACY_REDUNDANT`.
- Новый Core не требует EN-трассирования через `J20`: ветка выбирается явным `normative_system=SP_RK_EN`; `J20` сохраняется только для проверки legacy Excel.

## C. Какие данные нужно извлечь

1. Локальные таблицы покрытий, настила, профилей и расчётные матрицы прогонов.
2. Таблицы пролетов 9/12/15/18/21/24 м и климатические lookup основной книги.
3. Списки `нормы` (`старым`/`новым`) и `утеплитель` (150/200/250) как validation metadata.
4. Локальные оконные SP_20/SP_RK_EN blocks, glazing mapping и коэффициенты типов 1–5.

## D. Есть ли активная формула, которую невозможно воспроизвести по имеющимся данным?

Да, для произвольного входного сценария: exact city membership вне экспортированного локального snapshot и некоторые upstream lookup остаются недоказанными. Нормативные ветки окон (`SP_20`/`SP_RK_EN`) и их формульная цепочка локально доступны; внешние `[3]`/`[4]`/`[5]` не нужны.

## E. Оставшиеся UNKNOWN

- причина 244 расхождений локальной таблицы городов с cache проверяемой версии;
- точная версия/inputs/methodology старой книги `[4]`;
- точная причина legacy blank `J20` (ошибочная ссылка или ручной переключатель) остаётся исторической неизвестностью, но не API blocker;
- инженерская семантика безымянного `Подбор прогонов 2!R28`;
- корректный ожидаемый результат проблемной ветки 24 м;
- потерянная ссылка в `B73:B76,B128:B131` для шага 500 мм.

## F. Bugs/anomalies для compatibility mode

- условно достижимый `#REF!` при шаге прогонов 500 мм;
- `#N/A` как исключение кандидата и как реальная ошибка выбранного результата;
- обращения legacy D9/F9 к пустому `J20`; новый маршрут их не использует;
- строковые sentinels `"0"`, `"-"`, пустые строки и число 0;
- `вывод!F35=85` как константа;
- `вывод!D69` строго кг/м²;
- first-match и tie-breaking по порядку исходных таблиц;
- ветка 24 м с текущими `#N/A`, пока не утверждено исправление.

## G. Реальные пользовательские inputs

Город; пролет, длина и высота; коэффициент ответственности; явный `normative_system`; необязательный ручной шаг рам; покрытие; марка настила; флаги дополнительных прогонов; необязательный флаг усиленных связей; количества ворот/дверей; параметры окон и обязательный `window_type=1..5` при включённых окнах. Материал стены не является входом Core 1.

## H. Outputs для Core 2

Выбранные балка/колонна/прогоны и сталь, effective frame step, шаг и обе массы прогонов, все вторичные сечения, пластины, болты, М16, фасонки, оконные ригели, масса проёмов, инженерные нагрузки, `kg_per_m2` и diagnostics. Core 2 не делает повторный инженерный выбор.

## I. Готов ли Core 1 к реализации?

Архитектура, контракты и автономная ветка прогонов готовы. Локальные
оконные снеговые/ветровые листы и per-type коэффициенты 1–5 считаются
доказанными для реализации. Полный parity окон нельзя принять до non-zero
golden oracle; J20/ID3/ID4/ID5 не являются blockers нового Core.

## Доказанные blockers

1. Для произвольного города вне локального snapshot не доказан exact membership result.
2. Ненулевой оконный numeric oracle пока не зафиксирован, поэтому parity не закрыт.
3. Код `WindowGirtCalculator` ещё не написан; формульная цепочка и коэффициенты типов 1–5 доказаны.
4. В прогонных матрицах условно достижимы разрушенные ссылки для шага 500 мм.
5. Ветка пролёта 24 м содержит активные `#N/A` и не подтверждена как корректная.
