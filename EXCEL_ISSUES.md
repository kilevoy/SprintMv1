# EXCEL_ISSUES — Sprint M, stage A

Ниже перечислены обнаруженные проблемы и подозрительные места. Ничего не исправлялось.

## Критические для воспроизводимости

1. `MISSING EXTERNAL SOURCE`: отсутствует `Подбор прогонов v4.3 - фикс шага.xlsx`.
2. `MISSING EXTERNAL SOURCE`: отсутствует `Подбор прогонов v4.3.xlsx`.
3. `MISSING EXTERNAL SOURCE`: отсутствует предрасчет колонн v4.0.
4. `LEGACY TRACE ONLY`: основная книга ссылается на `Подбор оконых ригелей.xlsx`, а предоставлена версия `v2.0`; локальная оконная ветка основной книги canonical для Core 1.
5. `LEGACY TRACE ONLY`: предоставленная таблица нагрузок имеет совпадение около 82,4% с кэшированным external-link источником; Core 1 использует локальные снеговые/ветровые листы и не требует ID3.

## Ошибки и подозрительные места книги нагрузок

`Таблица нагрузок по городам.xlsx` содержит 42 маркера ошибок на `СП 20` и 182 на `СП РК EN`. Книга сама по себе не имеет внешних ссылок, поэтому ошибки являются внутренними lookup/данными и должны быть отдельно классифицированы перед использованием как нормативный источник.

## Ошибки книги оконных ригелей v2.0

- `Лист1!J18` сейчас имеет кэшированный `#N/A`; управляющая `K18` возвращает `нет`, поэтому `J19` блокирует использование внешнего lookup.
- На `Ветер по СП РК EN` обнаружены многочисленные маркеры ошибок (около 114 по инвентарному сканированию); часть связана с отсутствием корректного города/нагрузки и требует проверки после подстановки согласованной таблицы нагрузок.
- Наличие внутреннего листа `Ветер СП` не устраняет зависимость от городской таблицы для выбора исходной ветровой нагрузки.

## Формульные и архитектурные риски

- Внешние формулы используют абсолютные диапазоны до строк 1000 и `INDEX/MATCH`; при замене источника нужно сохранить названия листов, структуру колонок и диапазоны.
- В подборе оконных ригелей используется sentinel `999999999` для недопустимых вариантов. Если все кандидаты недопустимы, итоговый `SMALL` может вернуть sentinel, а не явную диагностическую ошибку.
- В основной книге есть локальные именованные диапазоны `нормы`, завязанные на внешние ссылки `[1]`/`[2]`; при переносе формул необходимо проверить область действия имени (`localSheetId`).
- Встречаются точные и приближенные режимы `MATCH`; изменение сортировки lookup-таблиц может менять результат без изменения формулы.
- В основной книге присутствует `calcChain.xml`, но это не гарантирует актуальность кэшированных результатов после перемещения/замены внешних книг.

## Неисправленные по инструкции

Все перечисленные проблемы только зафиксированы. Код не писался, Excel-файлы не изменялись, внешние ссылки не перепривязывались, ошибки не подавлялись и не заменялись предположительными значениями.

## A.1 — классификация ошибок по влиянию

| Ошибка/область | Классификация | Влияние |
|---|---|---|
| `#REF!` в `Расчеты`, `Расчеты МП390`, `Расчеты 2`, `Расчеты МП390 2` | Результат отсутствующих внешних файлов и/или разрушенных ссылок; не штатное состояние | Способна изменить подбор прогонов и итоговую металлоёмкость, если ветка прогонов активна |
| `#DIV/0!` в `Подбор прогонов` | Реальная формульная ошибка либо отсутствующий расчетный знаменатель; не штатное состояние | Способна повлиять на шаг/профиль прогонов и итоговую массу |
| `#VALUE!` в `Подбор прогонов` и `снегветер` | Реальная ошибка данных/типа или несовместимость ветки; не штатное состояние | Может влиять на климат, подбор и конечный результат при прохождении соответствующей ветки |
| `#N/A` в `24м`, `подбор`, `снегветер` | Ошибка lookup/неполные климатические данные; не считать штатной | Потенциально влияет на вариант каркаса для выбранного пролета/города; для `24м` влияние существенное |
| `#N/A` в `Лист1!J18`, `Лист7!J18` | Ожидаемый результат отсутствующего города в выбранном внешнем lookup, но функционально блокирующее состояние | Для текущего города `Роза` окно не находится в `СП РК EN`; может отключить/изменить оконную ветку |
| `#N/A` в `Ветер СП`, `Ветер по СП РК EN` | Для неиспользуемых строк может быть следствием отсутствующих входов; для активной строки — реальная ошибка доступности ветра | Влияет на ветровую нагрузку ригелей и оконную массу при активной нормативной ветке |
| `#N/A` в переданной таблице нагрузок | Внутренние lookup/data gaps; не штатный результат для города, который должен быть найден | Текущая основная книга напрямую использует только `СП РК EN!B:C`; остальные ошибки влияют через v2.0 при принятии её как замены |
| `999999999` в оконном подборе | Штатный sentinel для недопустимого кандидата, не Excel-ошибка | Сам по себе нормален; если все кандидаты получили sentinel, итоговый подбор становится недоступным и это должно быть диагностировано отдельно |

### Текущий сценарий

Основная книга сейчас использует город `Роза`. В legacy lookup `Лист1!J18` и
`Лист7!J18` имеют `#N/A`; это сохраняется для compatibility trace. Новый Core
маршрутизирует нормативную ветку явно и не блокируется отсутствием ID3/ID4/ID5.

## Что доказать нельзя по одному кэшу

Внешний кэш сохраняет значения, но не исходные формулы, даты обновления источника и историю пересчета. Поэтому по каждой строке из `SOURCE_COMPARISON.md` можно установить факт расхождения и возможное влияние, но нельзя надежно отличить изменение формулы от изменения входных данных или устаревшего кэша без оригинального внешнего файла.
